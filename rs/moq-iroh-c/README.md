# moq-iroh-c

Media over QUIC between [iroh](https://iroh.computer) endpoints, as a small C ABI
for a host that runs its own `poll()` loop (ghostty-agent is the first).

Why not the existing bindings: `moq-ffi` is UniFFI (RustBuffer and foreign-future
calls, made for generated wrappers), and `libmoq` delivers through callbacks on
its runtime thread and has no way to accept sessions or reach iroh. Here nothing
calls back into the host: results are queued, a descriptor wakes the host, and
the host pulls.

```c
#include "moq_iroh.h"

moqi_node_config cfg = { .secret_path = "key.hex", .relay = "default", .port = 0 };
int32_t node = moqi_node_new(&cfg);             // an iroh endpoint serving a moq origin
int32_t pub = moqi_publish(node, "netlab", "frames");
moqi_publish_object(pub, bytes, len, /*new_group=*/true);

// on another host, with the first one's ticket (moqi_node_ticket)
int32_t sub = moqi_subscribe(peer, ticket, "netlab", "frames", /*max_age_ms=*/500);
// poll() moqi_wake_fd(); then moqi_wake_clear() and drain:
moqi_object o;
while (moqi_read(sub, &o, buf, sizeof buf) == 1) { /* o.group, o.index, o.len ... */ }
```

The header is `include/moq_iroh.h`, generated by `build.rs`; a test fails when
the committed copy is stale. The release workflow ships `libmoq_iroh.a` and the
header for linux-x64.

## Relay modes

`"default"`: n0's public relays and address lookup, so a bare endpoint id is
enough to dial. `"off"`: direct paths only; tickets carry the addresses. A URL:
only that relay (for example `iroh-relay --dev`), no address lookup.

## `moqi_stats` JSON

| Field | Meaning |
|---|---|
| `id`, `id_short`, `ticket` | this endpoint, and what a peer needs to dial it |
| `relay_mode`, `relays[] {url, connected}` | the home relay and whether it is connected |
| `addrs[]` | direct addresses the endpoint knows for itself |
| `conns[] {n, dir, peer, peer_short, age_ms, open, closed_why}` | every connection, `in` (a peer subscribing to us) or `out` (we dialed) |
| `conns[].paths[] {id, kind, addr, selected, rtt_us}` | its network paths: `relay` or `direct`, which one carries the data, the round-trip time of each |
| `conns[].moq {bytes, frames, groups, subs, stale_groups, stale_frames}` | moq-net's own counters for the session: egress on `in`, ingress on `out` |
| `events[] {t_ms, conn, what, kind, addr}` | the path timeline: `opened`, `selected`, `closed`, `gone` |
| `pubs[] {h, broadcast, track, group, index, groups, objects, bytes}` | publishers and where their live edge is |
| `subs[] {h, peer, state, why, conn, group, index, latest, behind, objects, groups, skipped, cut, late, dropped, queued, lat_us, lat_avg_us, max_age_ms, throttle_ms}` | subscriptions: `skipped` groups moq never delivered, `cut` groups it gave up on part way, latency from the publisher's clock to ours |

Latency uses both hosts' wall clocks (each object carries the publisher's), so
between machines it is only as good as their clock sync.

## Falling behind

A subscription's `max_age_ms` is moq's `Subscription::max_age`: a group further
behind the newest than that is skipped rather than queued, and one being read
when that happens is cut short. `moqi_subscribe_throttle` makes a subscription
read slowly on purpose, to show it.
